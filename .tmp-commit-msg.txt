修 CI test job 失败的真正原因：11 个套件硬编码了 Windows 浏览器路径

## 根因

每个套件各自抄了一份：

  C:/Users/Admin/AppData/Local/ms-playwright/chromium_headless_shell-1234/
  chrome-headless-shell-win64/chrome-headless-shell.exe

在 Windows 上这个文件真实存在 → 本地 14 个套件全绿；
在 ubuntu runner 上不存在 → chromium.launch() 立刻抛错。
入场的 12 个套件里有 9 个是这么写的，所以 test job 连挂两次。

失败点正好落在套件列表前三个（e2e-equipment / e2e-landing / e2e-optimize），
与之前观察到的「跑到约第 3 个套件挂掉」吻合。
之所以一直没定位到：GitHub 的 job logs 端点要 admin 权限（403），
拿不到具体报错，只能靠「本地绿、CI 红」这种侧面线索反推。

## 改动

- 11 个套件改用 e2e-setup.cjs 的跨平台探测（它按平台扫 ms-playwright，
  Windows / Linux / macOS 都覆盖）。
- 顺手把另外 15 个入库的诊断/审计/截图脚本也一并改掉 ——
  它们同样是长期工具（.gitignore 里明确写着「本项目自己的工具」），
  硬编码路径同样是隐患。
- e2e-run-all.cjs 新增预检 assertNoHardcodedBrowserPath()：
  跑测试前扫描所有 .cjs，发现硬编码路径直接失败并指出行号。
  这类 bug 的排查成本远高于写这一行，必须拦在源头。
- deploy-pages.yml 的注释补上根因记录（continue-on-error 暂留，
  等 CI 确认转绿后再去掉）。

## 验证

本地 npm test：14 个套件全部通过，0 失败（3m11s）。
全部 39 个 .cjs 通过 node --check。
